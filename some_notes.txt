The gmp-mpfr-sys crate provides Rust bindings for three C libraries: GMP, MPFR, and MPC.

When the use-system-libs feature is enabled:

The crate attempts to link dynamically to your operating system's installed versions of these libraries.
For this to work on Fedora, you would need to have the development headers installed (e.g., gmp-devel, mpfr-devel, and libmpc-devel) because the Rust compiler needs them to generate the native bindings. If any of those are missing or the system library versions are incompatible with what the crate expects, the build process will throw an error (often complaining about missing MPC or MPFR).
By removing use-system-libs (changing it to just "1.6.5"):

You are telling the crate not to look for the system's C libraries.
Instead, gmp-mpfr-sys will download the source code for GMP, MPFR, and MPC, and compile them locally as part of your Rust build process. It will then statically link these bundled, known-compatible versions directly into your application.
This makes your build self-contained and isolated from your Linux distribution's specific package versions. I can see you just installed autoconf, automake, and libtool in your terminal—these are the exact build tools the crate needs to successfully compile those bundled C libraries from source in the background.

The reason you need the operation::OperationLike import now is because the melior dependency was upgraded.

According to the output from git diff HEAD~1 analyzer/Cargo.toml, your project recently changed the melior dependency version from "0.24.0" to "0.26.9".

In older versions of melior (like 0.24.0), OperationRef and similar struct types directly implemented those methods. However, in newer versions of the crate (starting around v0.25.0+), the developers of melior refactored the API and moved many core operation utilities into the generic OperationLike trait. This forces consumers of the API to explicitly import the trait in order to access methods like .name(), .attribute(), and .next_in_block() on the operation types.

Because the underlying API architecture changed across those versions, the explicit import use melior::ir::operation::OperationLike; is now mandatory.
